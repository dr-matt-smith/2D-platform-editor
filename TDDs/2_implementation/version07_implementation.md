## Constraints & approach

- The §4 table is **the spec and the regression gate**. Correctness is
  proven by two pure unit tests, not by eyeballing renders:
  1. `tileMask` returns the §4 mask for all 16 neighbour combinations.
  2. The Dirt `tile_lookup.json` maps every mask to the **same tile the v6
     code drew** (the §4 `index` column).
  Together these are airtight: the per-tile PNGs `00..23` are exact atlas
  crops and `24..27` are the same standalone PNGs v5/v6 already drew, so
  blitting `lookup[mask]` is pixel-identical to the old index path.
- **Pre-confirmed:** all 16 PNGs referenced by §4 already exist in
  `tiles/` (verified). No new slicing — this resolves design §11 Q1; the
  resolver loads existing PNGs keyed by mask.
- **Blast radius is small:** only `renderer.js` and `renderer.test.js`
  import `autotileIndex`/`pickTile`/`PLATFORM`; `main.js` uses `draw()`
  only. Removing them touches nothing else.
- **Decor untouched.** grass/drip/moon/stars/sky/cave keep the existing
  `drawTile(index)` atlas path. v7 only re-routes the *filled-terrain* pass
  through the mask→lookup resolver, and re-expresses decor *suppression* as
  `THIN` masks.

2. Add `const THIN = new Set([0,1,2,4,5,8,10])` (single, four caps, mid-v,

   `tileMask(fixture)===mask` for every neighbour combo (incl. an
   off-grid/border case), plus the existing draw/decor tests adjusted to the
   new internals. Suite stays green; example render unchanged.

## Risks & sequencing

- **M1 before M2 deliberately.** Splitting "compute the mask" from "resolve
  via JSON" means M1 changes *zero* pixels (interim literal map) and is
  proven by the mask test alone; M2 swaps the source with the mapping test
  as the guarantee. If a regression appears it is unambiguously in one step.
- **Pixel-identity argument must hold.** It relies on `tiles/00..23` being
  exact atlas crops. If any differ from the atlas, the mapping test passes
  (basenames match) but the render could shift. Mitigation: M2's scratch
  harness compare catches that; if it ever diverges, treat the slice PNGs
  as the source of truth going forward (they are what v8 tilesets use
  anyway).
- **`# theme:` ↔ `background`.** v7 keeps `# theme:` selecting
  `background.sky|cave`; no format change. Confirm the cave/sky bg still
  draws via the existing decor/bg path (it does — that path is untouched).
- **No test-count regression expected** beyond the rewrite; suite remains
  green. No automated DOM/canvas test (standing gap since v2); engine
  correctness here is fully unit-provable, which is stronger than usual.
